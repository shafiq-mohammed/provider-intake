# Provider Document Intake — SPEC

Source: docs/REQUIREMENTS.md. Ticket format: docs/TICKET_TEMPLATE.md. Stack and rules: CLAUDE.md.

## 1. Goal

A behavioral health provider uploads one credential document (jpg, png, or pdf, max 10 MB). The
service extracts raw text (pypdf text layer or an OCR engine), asks an LLM to map that text onto
four fields (provider name, license number, state, expiration date), deterministically validates
and normalizes the LLM's answer, and returns per-field results that say what was found, what was
not, and why. A single static HTML page lets a human upload a file and see the result.

## 2. Non-goals (out of scope for every ticket)

- Authentication, authorization, multi-tenancy.
- Persistence beyond process memory. No database, no files on disk.
- Batch uploads, multi-page/multi-document workflows, human review queue.
- Deployment, containers, CI configuration.
- Any OCR system binary (tesseract etc.). None is installed and none will be added.
- A JS framework, bundler, or build step for the UI.
- Verifying a license against a licensing board or any external registry.
- License-number format validation per state (formats vary; the value is passed through).
- Streaming or chunked upload handling; the whole body is read into memory.
- Caching of OCR or LLM results between calls.

## 3. Decisions made by the human (recorded, not re-derived)

D1. OCR sits behind a protocol, exactly like the LLM. `OcrEngine.extract_text(content: bytes,
    content_type: str) -> str`, with a `FakeOcrEngine` used by every test. The real adapter uses
    Claude vision; for PDFs the pypdf text layer is tried first and vision is the fallback. No new
    system binaries. (The pypdf-first routing lives in `text_extraction.extract_text`, which is
    shared by all engines; the Anthropic engine therefore only ever receives PDF bytes whose text
    layer was empty or thin, and sends them to Claude as a document block.)

D2. Uncertainty is per-field status plus issue codes, not a confidence score. Each of the four
    fields is a `FieldResult {value, status, raw, issues[]}`, `status` is one of
    `found | not_found | unreadable | invalid`, and the response carries a top-level
    `missing_fields` list. Deterministic validation may only DOWNGRADE a field's status, never
    upgrade it. Example:
    `{"expiration_date": {"value": null, "status": "invalid", "raw": "Jan 32 2024", "issues": ["unparseable_date"]}, "missing_fields": ["state"]}`

D3. The UI is one hand-written static HTML page served at `GET /`, in its own ticket: file
    picker, the 10 MB limit stated upfront before upload, and a results table showing each
    field's status and issues. No build step, no framework, no JS bundler.

D4. Exactly seven tickets, in the order and with the dependencies listed in section 13. LLM
    extraction (T-004) and deterministic validation (T-005) are separate tickets. The real
    Anthropic adapters are last (T-007) and their live tests skip without an API key.

## 4. Assumptions (made where requirements were vague; a human reviews these)

A1. `python-multipart` must be added to `[project].dependencies` in pyproject.toml in T-002.
    FastAPI cannot parse multipart forms without it, it is not installed today, and it is a pure
    Python package (not a system binary). If the human vetoes this, T-002 must switch
    `POST /documents` to a raw-body upload and the UI must send the file as the request body.
A2. The uploaded part's declared content type is the source of truth for the media type, and it
    must be exactly one of `application/pdf`, `image/jpeg`, `image/png`. `image/jpg` and
    `application/octet-stream` are rejected with 415. In addition the first bytes must match the
    declared type's signature (`%PDF`, `\xff\xd8\xff`, `\x89PNG\r\n\x1a\n`); a mismatch is 415
    `content_type_mismatch`. This keeps corrupt or mislabeled files from reaching pypdf.
A3. The size limit is enforced on the decoded file bytes (`len(content) > max_upload_bytes`),
    not on the `Content-Length` of the multipart envelope. The whole body is read into memory.
A4. Document ids are `uuid4` strings generated by the repository. Metadata has no timestamps.
A5. Computation endpoints (`/text`, `/extract`) are `POST` because they trigger paid external
    calls and are not cacheable. They are idempotent with respect to stored state (nothing is
    persisted; results are recomputed on every call).
A6. "Thin" PDF text layer means fewer than `Settings.min_pdf_text_chars` (default 20)
    non-whitespace-stripped characters. Any pypdf exception is treated as an empty text layer
    and falls through to the OCR engine; it is never a 500.
A7. OCR text that is empty after `strip()` short-circuits: the field extractor is not called
    and every field is `not_found` with issue `no_text`.
A8. Status certainty rank: `found=3 > invalid=2 > unreadable=1 > not_found=0`. Validation only
    ever transforms `found` fields (to `found` with a normalized value, or to `invalid`); any
    field whose incoming status is not `found` is returned unchanged. `value` is always `null`
    when `status != found`; this is enforced by the `FieldResult` model itself.
A9. An expiration date in the past is `status = invalid`, issue `expired`, and `value` is `None`
    like every other non-`found` field (A8 is strict, no exception). The date stays visible to
    the user in `raw`, as the document itself spelled it. A date equal to today is not
    expired. `missing_fields` lists every field whose status is not `found`, so an expired
    license appears there (it is not a reliably valid value).
A10. Numeric dates are US order (`MM/DD/YYYY`). Two-digit years are unparseable. Accepted
    formats are the explicit `DATE_FORMATS` list in section 11 (T-005). Nothing else parses.
A11. State normalization covers the 50 states plus DC, matched case-insensitively by full name
    or two-letter code after stripping whitespace and trailing punctuation. Territories are
    `unknown_state`.
A12. Provider name and license number get only whitespace stripping; blank values become
    `invalid` with issue `empty_value`. No further format rules.
A13. `create_app()` with no settings uses `Settings()` defaults, never the environment, so tests
    are hermetic. Only the module-level `app` in `src/app/main.py` reads the environment via
    `Settings.from_env()`.
A14. Default Anthropic model id is `claude-sonnet-5`, overridable with `APP_ANTHROPIC_MODEL`.
A15. Live T-007 tests need `ANTHROPIC_API_KEY` in the environment and sample documents placed
    by the human at `tests/fixtures/sample_license.png` (required for the OCR live test) and
    optionally `tests/fixtures/sample_license.pdf`. Each live test skips if the key or its
    fixture file is absent. No sample documents exist in the repo today.
A16. Unhandled exceptions (bugs) still surface as a 500. Every anticipated bad-input path in
    this spec is mapped to a 4xx envelope; a 500 in a test is a defect, not expected behavior.
A17. Error `details` never contain document bytes or OCR text. Engine/extractor failures report
    only the exception class name. This binds the 422 handler too: pydantic's `exc.errors()`
    carries the rejected value under `input`, which for an upload is the document content, so
    validation errors are projected to `type`/`loc`/`msg` by `safe_validation_errors()`.
    (Corrected during T-002 review, which found the raw passthrough echoing uploaded bytes
    back to the client. A17 wins over the earlier literal `jsonable_encoder(exc.errors())`.)

## 5. Stack and conventions

- Python 3.11+, FastAPI, pydantic v2, pypdf, anthropic SDK; pytest + httpx (TestClient); ruff
  (line length 100, rules E F I B UP). Dependencies are in pyproject.toml; T-002 adds
  `python-multipart` (A1). Nothing else is added.
- Run: `uvicorn app.main:app --reload` with `src/` on the path. Tests: `python -m pytest -q`.
- App factory pattern: `create_app(...)` builds an isolated app with injected collaborators.
  Collaborators are stored on `app.state` (`settings`, `repository`, `ocr_engine`,
  `field_extractor`, `clock`) and read by routes via `request.app.state`.
- All response bodies are JSON except `GET /` (HTML). All errors use the envelope in section 9.
- Pydantic models for every request/response shape live in `src/app/models.py`.
- Protocols (`typing.Protocol`) define every external collaborator; fakes live next to the
  protocol and are the only implementations used in T-001..T-006 tests.
- Document bytes are never logged, never included in `repr`, never included in error details.
- Type hints everywhere; `from __future__ import annotations` is fine; no `Any` where a
  concrete type is known (the Anthropic client is the one sanctioned `Any`).

## 7. Request flow

```
POST /documents            -> validate_upload -> repository.add -> 201 DocumentMeta
POST /documents/{id}/text  -> repository.get -> extract_text(doc, ocr_engine) -> TextExtraction
POST /documents/{id}/extract
                           -> repository.get
                           -> extract_text(doc, ocr_engine)              (OcrError -> 422 ocr_failed)
                           -> if text blank: all not_found + "no_text"   (extractor not called)
                              else field_extractor.extract_fields(text)  (any exc -> 422 extraction_failed)
                           -> validate_result(result, today=clock())     (T-005; downgrade-only)
                           -> 200 ExtractionResponse
GET /                      -> static HTML; page calls GET /config, POST /documents, POST .../extract
```

## 8. Data model and storage

- `StoredDocument` (frozen dataclass): `id`, `filename`, `content_type`, `content: bytes`
  (excluded from `repr`), `size_bytes` property, `meta()` -> `DocumentMeta`.
- `DocumentRepository` protocol with `add(*, filename, content_type, content) -> StoredDocument`
  and `get(document_id) -> StoredDocument | None`. `InMemoryDocumentRepository` is a dict keyed
  by id, one instance per app, created by `create_app` unless injected.
- Extraction results are not stored. Every `/text` and `/extract` call recomputes.

## 9. Error handling

Envelope, always:

```json
{"error": {"code": "<snake_case>", "message": "<human readable>", "details": {}}}
```

`details` is always a JSON object (`{}` when there is nothing to add). Handlers registered by
`register_error_handlers(app)`:

| Trigger                                   | Status | code                        | details                                              |
|-------------------------------------------|--------|-----------------------------|------------------------------------------------------|
| `ApiError` raised anywhere                | its own| its own                     | its own (or `{}`)                                    |
| `fastapi.exceptions.RequestValidationError` | 422  | `validation_error`          | `{"errors": safe_validation_errors(exc)}`            |
| Starlette `HTTPException` (unknown route) | 404    | `not_found`                 | `{}`                                                 |
| Starlette `HTTPException` (bad method)    | 405    | `method_not_allowed`        | `{}`                                                 |
| Starlette `HTTPException` (other)         | its own| `http_error`                | `{}`                                                 |
| upload: declared type not allowed         | 415    | `unsupported_media_type`    | `{"content_type": str, "allowed_content_types": [..]}` |
| upload: bytes too large                   | 413    | `file_too_large`            | `{"max_upload_bytes": int, "size_bytes": int}`       |
| upload: zero bytes                        | 400    | `empty_file`                | `{}`                                                 |
| upload: signature does not match type     | 415    | `content_type_mismatch`     | `{"content_type": str}`                              |
| unknown document id                       | 404    | `document_not_found`        | `{"document_id": str}`                               |
| OCR engine raised                         | 422    | `ocr_failed`                | `{"reason": "<exception class name>"}`               |
| field extractor raised                    | 422    | `extraction_failed`         | `{"reason": "<exception class name>"}`               |

Upload checks run in this order: declared type -> size -> empty -> signature. Every check is
single-condition in tests so the order only matters for the implementation.

Field-level issue codes (the `issues` list on a `FieldResult`):

| code               | set by  | meaning                                                          |
|--------------------|---------|------------------------------------------------------------------|
| `no_text`          | T-004   | OCR produced no text; extractor not called; every field carries it |
| `empty_value`      | T-005   | status was `found` but value was null/blank                       |
| `unknown_state`    | T-005   | state value is not a US state name or code                        |
| `unparseable_date` | T-005   | expiration date matched none of `DATE_FORMATS`                    |
| `expired`          | T-005   | expiration date is before today                                   |
| `unknown_status`   | T-007   | the model returned a status outside the enum; coerced to `unreadable` |

The LLM may also return arbitrary issue strings; they are preserved as-is and appended to.

**Division of labour (T-008): the model transcribes and observes; deterministic validation decides
validity.** `EXTRACTION_PROMPT` asks the model to transcribe what is present and *not* to judge
authenticity, genuineness or format. When it doubts a legible value it keeps `status: found` and
records the doubt as a short snake_case issue code beside the value rather than in place of it.

- The four T-005 codes (`empty_value`, `unknown_state`, `unparseable_date`, `expired`) are set by
  `validate_field` / `validate_result`. `no_text` (T-004) and `unknown_status` (T-007) are also set
  and interpreted by our code; everything else in `issues` is advisory.
- Advisory codes the model invents (`appears_fictional`, `low_contrast`, `handwritten`, …) are
  preserved verbatim, are never interpreted, and never by themselves downgrade a status or null a
  value. Deterministic codes are *appended* to them, never substituted — an expired licence the
  model also doubted reads `["appears_fictional", "expired"]`.
- `invalid` is reserved for deterministic validation. The prompt tells the model never to return
  it, and **the prompt is the only mechanism**: `parse_extraction_json` does not rewrite a *valid*
  status the model sends, because coercing one would be our code raising certainty, which A8
  forbids. (A status outside the enum is a different case: it becomes `unreadable` +
  `unknown_status`.) A non-compliant model can still return `invalid`, and that stands.

Why: a novelty document whose licence number read `SARCASM` came back `invalid` with the model's
own codes, so A8 nulled the value and the field was reported as undeterminable — even though the
text had been read correctly and our validator, which has no licence-number format rules (A12),
would have passed it through. Transcription and judgment are now separated.

## 10. Testing conventions

- One file per ticket: `tests/test_T-00X_<slug>.py`. Test names `test_ac<N>_<what>`.
- Build apps with `create_app(...)` and `fastapi.testclient.TestClient`; never import the
  module-level `app`. Inject `FakeOcrEngine`, `FakeFieldExtractor`, `InMemoryDocumentRepository`
  and a fixed `clock` through `create_app` keyword arguments.
- No test in T-001..T-006 touches the network or reads an API key. T-007's live tests are
  marked `skipif` on `ANTHROPIC_API_KEY` and on fixture presence.
- Multipart upload in tests: `client.post("/documents", files={"file": (name, data, ctype)})`.
- T-001 only: to exercise the error handlers before any real endpoint exists, a test may
  register a throwaway route on the app it built (`app = create_app(); @app.post("/_probe")`)
  that declares a pydantic body or raises `ApiError`. Handlers are app-level and apply to routes
  added after `create_app` returns, as long as no request has been made yet.
- Input fixtures (inputs only, never behavior under test):
  - PNG bytes: `b"\x89PNG\r\n\x1a\n" + b"\x00" * 32`
  - JPEG bytes: `b"\xff\xd8\xff\xe0" + b"\x00" * 32`
  - Blank PDF (empty text layer): `w = pypdf.PdfWriter(); w.add_blank_page(width=200, height=200); w.write(buf)`
  - PDF with a text layer, no extra libraries (verified: pypdf extracts the exact string):

    ```python
    def minimal_pdf(text: str) -> bytes:
        stream = f"BT /F1 12 Tf 20 100 Td ({text}) Tj ET".encode()
        objs = [
            b"<< /Type /Catalog /Pages 2 0 R >>",
            b"<< /Type /Pages /Kids [3 0 R] /Count 1 >>",
            b"<< /Type /Page /Parent 2 0 R /MediaBox [0 0 300 200] /Contents 4 0 R "
            b"/Resources << /Font << /F1 5 0 R >> >> >>",
            b"<< /Length " + str(len(stream)).encode() + b" >>\nstream\n" + stream + b"\nendstream",
            b"<< /Type /Font /Subtype /Type1 /BaseFont /Helvetica >>",
        ]
        out = bytearray(b"%PDF-1.4\n")
        offsets = []
        for i, obj in enumerate(objs, start=1):
            offsets.append(len(out))
            out += f"{i} 0 obj\n".encode() + obj + b"\nendobj\n"
        xref = len(out)
        out += f"xref\n0 {len(objs) + 1}\n".encode() + b"0000000000 65535 f \n"
        for off in offsets:
            out += f"{off:010d} 00000 n \n".encode()
        out += (
            f"trailer\n<< /Size {len(objs) + 1} /Root 1 0 R >>\nstartxref\n{xref}\n%%EOF\n"
        ).encode()
        return bytes(out)
    ```
    Avoid `(`, `)` and `\` inside `text`.
  - Corrupt PDF (valid signature, unreadable body): `b"%PDF-1.4 garbage"` (pypdf raises).
- Fixed clock for T-005: `clock=lambda: date(2026, 9, 11)`.
- Fixtures may build clients, repositories, fakes from `src/app`, and input bytes. They must
  not reimplement validation, routing, or parsing.

from dataclasses import dataclass, field
from typing import Protocol

@dataclass(frozen=True)
class StoredDocument:
    id: str
    filename: str
    content_type: str
    content: bytes = field(repr=False)     # never appears in repr()/str()/logs

    @property
    def size_bytes(self) -> int: ...
    def meta(self) -> DocumentMeta: ...

class DocumentRepository(Protocol):
    def add(self, *, filename: str, content_type: str, content: bytes) -> StoredDocument: ...
    def get(self, document_id: str) -> StoredDocument | None: ...

class InMemoryDocumentRepository:
    def __init__(self) -> None: ...
    def add(self, *, filename: str, content_type: str, content: bytes) -> StoredDocument:
        """Generates id = str(uuid.uuid4()), stores and returns the document."""
    def get(self, document_id: str) -> StoredDocument | None: ...
    def __len__(self) -> int: ...
```

def extract_text(

    """application/pdf: text = pdf_text_layer(content); if len(text.strip()) >= min_pdf_text_chars
    -> TextExtraction(source="pdf_text_layer"), engine NOT called.
    Otherwise (thin/empty layer, or any image type): engine.extract_text(content, content_type)
    -> TextExtraction(source="ocr"). Any exception from the engine is re-raised as OcrError."""
```

### T-004 — LLM field extraction and the per-field uncertainty model

```python
# src/app/models.py (added)
from enum import StrEnum
from pydantic import Field, computed_field, model_validator

FIELD_NAMES: tuple[str, ...] = ("provider_name", "license_number", "state", "expiration_date")

class FieldStatus(StrEnum):
    FOUND = "found"
    NOT_FOUND = "not_found"
    UNREADABLE = "unreadable"
    INVALID = "invalid"

    @property
    def rank(self) -> int:
        """found=3, invalid=2, unreadable=1, not_found=0 (higher = more certain)."""

class FieldResult(BaseModel):
    value: str | None = None
    status: FieldStatus
    raw: str | None = None
    issues: list[str] = Field(default_factory=list)
    # after-validator: if status != FOUND then value is forced to None (never rejected).

class ExtractionResult(BaseModel):
    provider_name: FieldResult
    license_number: FieldResult
    state: FieldResult
    expiration_date: FieldResult

    @computed_field
    @property
    def missing_fields(self) -> list[str]:
        """Names from FIELD_NAMES, in that order, whose status != found."""

    def fields(self) -> dict[str, FieldResult]:
        """{name: FieldResult} in FIELD_NAMES order."""

    @classmethod
    def all_with(cls, status: FieldStatus, *, issues: list[str] | None = None) -> "ExtractionResult":
        """Every field = FieldResult(status=status, issues=list(issues or []))."""

class ExtractionResponse(ExtractionResult):
    document_id: str
    text_source: Literal["pdf_text_layer", "ocr"]
```

`model_dump()` / JSON of `ExtractionResult` includes `missing_fields`. `FieldStatus` serializes
as its string value.

### T-005 — Deterministic normalization and validation rules

```python
# src/app/validation.py
from datetime import date

US_STATE_CODES: dict[str, str]
    # lower-case full name -> code, 50 states + "district of columbia" -> "DC"

DATE_FORMATS: tuple[str, ...] = (
    "%Y-%m-%d", "%m/%d/%Y", "%m-%d-%Y",
    "%B %d, %Y", "%b %d, %Y", "%B %d %Y", "%b %d %Y", "%d %B %Y", "%d %b %Y",
)

def normalize_state(raw: str) -> str | None:
    """strip whitespace and trailing '.,;', case-insensitive. Two-letter code in the code set
    -> upper-cased code; full name in US_STATE_CODES -> code; else None."""

def normalize_date(raw: str) -> date | None:
    """strip, collapse internal whitespace to one space, try DATE_FORMATS in order with
    datetime.strptime; first hit wins; None if nothing matches."""

def validate_field(name: str, field: FieldResult, *, today: date) -> FieldResult:
    """Returns a NEW FieldResult. If field.status != found: returned unchanged (equal).
    Otherwise, with raw := field.raw if field.raw is not None else field.value, and existing
    issues preserved (new codes appended, no duplicates):
      value None or blank        -> status invalid, value None, + "empty_value"
      provider_name / license_number -> status found, value stripped
      state    -> normalize_state; None -> invalid, value None, + "unknown_state"
                  else found, value = code
      expiration_date -> normalize_date; None -> invalid, value None, + "unparseable_date"
                  parsed < today -> invalid, value None, + "expired" (raw keeps the original)
                  else found, value = ISO "YYYY-MM-DD"
    Invariant: result.status.rank <= field.status.rank, always."""

def validate_result(result: ExtractionResult, *, today: date) -> ExtractionResult:
    """validate_field applied to each of FIELD_NAMES; returns a new ExtractionResult
    (missing_fields recomputes automatically)."""
```

`create_app(..., clock=None)`: `None` -> `datetime.date.today`; stored on `app.state.clock`.
`POST /documents/{id}/extract` now applies `validate_result(result, today=clock())` to the
extractor's output before building the response. The `no_text` short-circuit result is also
passed through `validate_result` (a no-op, since nothing is `found`).

Contract of `src/app/static/index.html` (plain HTML + inline vanilla JS, no external assets):

- `<p id="max-upload">` — on load the script does `fetch("/config")` and writes
  `Maximum file size: <N> MB (<max_upload_bytes> bytes). Accepted: <types>` into it. The upload
  button `<button id="upload" type="submit" disabled>` is disabled until `/config` has loaded.
- `<input type="file" id="file" name="file" accept="application/pdf,image/jpeg,image/png" required>`
- Client-side guard: if `file.size > max_upload_bytes` the script shows a message in
  `<p id="error" role="alert">` and does not upload.
- Submit: `POST /documents` (multipart, part name `file`), then `POST /documents/{id}/extract`.
  Any envelope error shows `error.message` (and `error.code`) in `#error`.
- `<table id="results">` with exactly these rows in this order, each with three cells:
  `<tr data-field="provider_name">`, `<tr data-field="license_number">`,
  `<tr data-field="state">`, `<tr data-field="expiration_date">`; cells
  `<td data-cell="value">`, `<td data-cell="status">`, `<td data-cell="issues">`.
- `<p id="missing-fields">` lists `missing_fields` joined by ", " (or "none").
- `<p id="document-meta">` shows filename and size after upload.
- **Value cell (T-009):** `<td data-cell="value">` shows `value`; when `value` is null it falls back
  to `raw` and carries `data-unconfirmed="true"`; when both are null it shows the em-dash
  placeholder, unmarked. A8 nulls `value` for every non-`found` status, so an expired date, an
  unparseable date and an unknown state would otherwise all display as a dash with the document's
  own text invisible to the reader. The marker must be *removed* as well as set — cells are reused
  across uploads — and it carries a visible style, not only an attribute, so the distinction
  survives for a reader who cannot perceive colour. **Display only: `value` stays null in the JSON
  and the field stays in `missing_fields`.**
- The JS function names `render` and `clearResults` are contract, not incidental: the T-006 and
  T-009 suites locate the render logic by those names.

### T-007 — Real Anthropic adapters selected by settings

```python
# src/app/anthropic_adapters.py
from typing import Any
import anthropic

OCR_PROMPT: str          # "Transcribe all text in this document verbatim…"
EXTRACTION_PROMPT: str   # asks for JSON with the four FIELD_NAMES, each {value,status,raw,issues}

def response_text(message: Any) -> str:
    """Concatenates block.text for every block in message.content with block.type == "text"."""

class AnthropicOcrEngine:
    def __init__(self, client: Any, model: str, *, max_tokens: int = 4096) -> None:
        """client: anthropic.Anthropic or any object exposing messages.create(**kwargs)."""
    def extract_text(self, content: bytes, content_type: str) -> str:
        """One messages.create call. image/jpeg|image/png -> content block
        {"type": "image", "source": {"type": "base64", "media_type": content_type, "data": b64}};
        application/pdf -> {"type": "document", "source": {"type": "base64",
        "media_type": "application/pdf", "data": b64}}; followed by {"type": "text", "text": OCR_PROMPT}.
        Other content types -> OcrError. Any exception from the client -> OcrError."""

class AnthropicFieldExtractor:
    def __init__(self, client: Any, model: str, *, max_tokens: int = 1024) -> None: ...
    def extract_fields(self, text: str) -> ExtractionResult:
        """One messages.create call with EXTRACTION_PROMPT + the text; returns
        parse_extraction_json(response_text(message)). Client exceptions -> ExtractorError."""

def parse_extraction_json(text: str) -> ExtractionResult:
    """Strips optional ``` / ```json fences and surrounding whitespace, json.loads.
    Top level must be an object, else ExtractorError. For each name in FIELD_NAMES:
      missing or non-object -> FieldResult(status=not_found)
      status not in FieldStatus -> status unreadable, issues + ["unknown_status"]
        (FieldResult then nulls `value` per A8, so the model's claimed value does not survive)
      value/raw non-string and not None -> str(); issues non-list -> []
    Malformed JSON -> ExtractorError."""

def make_client(settings: Settings) -> anthropic.Anthropic:
    """anthropic.Anthropic(api_key=settings.anthropic_api_key); ValueError if key is None/empty."""
```

`build_ocr_engine` / `build_field_extractor` (in ocr.py / extraction.py) gain the branch:
`"anthropic"` -> `AnthropicOcrEngine(make_client(settings), settings.anthropic_model)` /
`AnthropicFieldExtractor(make_client(settings), settings.anthropic_model)`. With
`anthropic_api_key` unset this raises `ValueError` from `create_app` (fail fast at startup).
Selecting the backend at runtime: `APP_OCR_BACKEND=anthropic APP_EXTRACTOR_BACKEND=anthropic
ANTHROPIC_API_KEY=…`.
