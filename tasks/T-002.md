# T-002: Upload endpoint, file validation, in-memory document repository

Status: in_review
Depends on: T-001

## Goal
A client can learn the upload limits from `GET /config`, upload one jpg/png/pdf of at most 10 MB via `POST /documents`, get its metadata back, and later fetch that metadata by id; every bad upload is a 4xx envelope.

## Scope
In:
- `src/app/models.py`: `DocumentMeta`.
- `src/app/repository.py`: `StoredDocument`, `DocumentRepository` protocol, `InMemoryDocumentRepository`.
- `src/app/uploads.py`: `SIGNATURES`, `content_matches_type()`, `validate_upload()`.
- `src/app/api.py`: router with `GET /config`, `POST /documents`, `GET /documents/{id}`; included by `create_app`.
- `create_app(..., repository=None)` keyword; `None` -> `InMemoryDocumentRepository()`; stored on `app.state.repository`.
- Add `"python-multipart"` to `[project].dependencies` in pyproject.toml (SPEC A1).
- `tests/test_T-002_upload.py`.
Out:
- Any reading of the bytes beyond the signature check (no pypdf, no OCR; T-003).
- Listing or deleting documents; timestamps on metadata.
- Streaming / `Content-Length` pre-checks; the body is read fully then measured (SPEC A3).
- Persisting anything to disk.

```python
# src/app/repository.py
from dataclasses import dataclass, field
from typing import Protocol

@dataclass(frozen=True)
class StoredDocument:
    id: str
    filename: str
    content_type: str
    content: bytes = field(repr=False)     # never appears in repr()/str()/logs

    @property
    def size_bytes(self) -> int: ...
    def meta(self) -> DocumentMeta: ...

class DocumentRepository(Protocol):
    def add(self, *, filename: str, content_type: str, content: bytes) -> StoredDocument: ...
    def get(self, document_id: str) -> StoredDocument | None: ...

class InMemoryDocumentRepository:
    def __init__(self) -> None: ...
    def add(self, *, filename: str, content_type: str, content: bytes) -> StoredDocument:
        """Generates id = str(uuid.uuid4()), stores and returns the document."""
    def get(self, document_id: str) -> StoredDocument | None: ...
    def __len__(self) -> int: ...
```

```python
# src/app/uploads.py
SIGNATURES: dict[str, tuple[bytes, ...]] = {
    "application/pdf": (b"%PDF",),
    "image/jpeg": (b"\xff\xd8\xff",),
    "image/png": (b"\x89PNG\r\n\x1a\n",),
}

def content_matches_type(content: bytes, content_type: str) -> bool:
    """True if content starts with any signature registered for content_type."""

def validate_upload(content: bytes, content_type: str | None, settings: Settings) -> None:
    """Raises ApiError in this order:
    415 unsupported_media_type  (content_type is None or not in settings.allowed_content_types)
    413 file_too_large          (len(content) > settings.max_upload_bytes)
    400 empty_file              (len(content) == 0)
    415 content_type_mismatch   (not content_matches_type(content, content_type))"""
```

Endpoints (T-002), router in `src/app/api.py`, included by `create_app`:

| Method | Path              | Request                                    | Response |
|--------|-------------------|--------------------------------------------|----------|
| GET    | /config           | –                                          | 200 `{"max_upload_bytes": int, "allowed_content_types": [sorted str]}` |
| POST   | /documents        | multipart/form-data, one part named `file` | 201 `DocumentMeta` JSON |
| GET    | /documents/{id}   | –                                          | 200 `DocumentMeta` JSON |

Errors (envelope `{"error": {"code", "message", "details"}}`):

| Trigger                                   | Status | code                     | details                                                |
|-------------------------------------------|--------|--------------------------|--------------------------------------------------------|
| missing `file` part                       | 422    | `validation_error`       | `{"errors": [...]}`                                    |
| declared type not allowed                 | 415    | `unsupported_media_type` | `{"content_type": str, "allowed_content_types": [..]}` |
| bytes too large                           | 413    | `file_too_large`         | `{"max_upload_bytes": int, "size_bytes": int}`         |
| zero bytes                                | 400    | `empty_file`             | `{}`                                                   |
| signature does not match declared type    | 415    | `content_type_mismatch`  | `{"content_type": str}`                                |
| unknown document id                       | 404    | `document_not_found`     | `{"document_id": str}`                                 |

Dependency change: add `"python-multipart"` to `[project].dependencies` in pyproject.toml (SPEC A1).

## Acceptance criteria
AC1. Given an app built with `create_app(repository=repo)` where `repo = InMemoryDocumentRepository()` When a client posts multipart `file=("license.png", <PNG bytes>, "image/png")` to `/documents` Then the response is 201 with `{"id": <non-empty str>, "filename": "license.png", "content_type": "image/png", "size_bytes": len(bytes)}`, `GET /documents/{id}` returns 200 with the identical body, `len(repo) == 1`, and `repr(repo.get(id))` does not contain the file bytes.
AC2. Given `create_app(Settings(max_upload_bytes=64))` When a client uploads a valid PNG of 65 bytes Then the response is 413 with `error.code == "file_too_large"` and `error.details == {"max_upload_bytes": 64, "size_bytes": 65}`; and a valid PNG of exactly 64 bytes is accepted with 201.
AC3. Given an app from `create_app()` When a client uploads a part declared `text/plain` Then the response is 415 with `error.code == "unsupported_media_type"` and `error.details.allowed_content_types == ["application/pdf", "image/jpeg", "image/png"]`; and When a client uploads bytes `b"not a png"` declared `image/png` Then the response is 415 with `error.code == "content_type_mismatch"` and `error.details == {"content_type": "image/png"}`.
AC4. Given an app from `create_app()` When a client uploads a zero-byte part declared `application/pdf` Then the response is 400 with `error.code == "empty_file"` and `error.details == {}`; and When the multipart body has no `file` part Then the response is 422 with `error.code == "validation_error"`.
AC5. Given an app from `create_app()` When a client calls `GET /config` Then the response is 200 with `{"max_upload_bytes": 10485760, "allowed_content_types": ["application/pdf", "image/jpeg", "image/png"]}`; and Given `create_app(Settings(max_upload_bytes=1024))` Then `max_upload_bytes` in the body is 1024.
AC6. Given an app from `create_app()` When a client calls `GET /documents/does-not-exist` Then the response is 404 with `error.code == "document_not_found"` and `error.details == {"document_id": "does-not-exist"}`; and `InMemoryDocumentRepository().get("x")` returns `None`.

## Test plan
- File: `tests/test_T-002_upload.py`. Fixture bytes from SPEC section 10: PNG `b"\x89PNG\r\n\x1a\n" + b"\x00" * 32`, JPEG `b"\xff\xd8\xff\xe0" + b"\x00" * 32`, PDF `b"%PDF-1.4\n" + b"%" * 32`. Upload with `client.post("/documents", files={"file": (name, data, ctype)})`.
- AC1: happy PNG; edge: JPEG and PDF each 201 with their content type; failure path: two uploads get distinct ids and `len(repo) == 2`.
- AC2: happy 413 at 65 bytes; edge: exactly `max_upload_bytes` accepted; failure path: 413 body is the envelope (no 500) even for a large payload of `max_upload_bytes + 1000`.
- AC3: happy 415 for `text/plain`; edge: `image/jpg` (not in the list) is 415 `unsupported_media_type`; failure path: mismatch check on PDF bytes declared `image/jpeg`.
- AC4: happy empty file 400; edge: missing part 422 in envelope; failure path: `validate_upload(b"", "application/pdf", Settings())` called directly raises `ApiError` with `status_code == 400`.
- AC5: happy default config; edge: custom settings reflected; failure path: `POST /config` -> 405 envelope.
- AC6: happy 404 envelope; edge: `GET /documents/%20` (id decodes to `" "`) is 404 `document_not_found`, and an id neighbouring a real one is 404; failure path: repository `get` on empty repo returns `None`.
  (Corrected during T-002: `GET /documents/` is not reachable as an empty id. Starlette answers it with a 307 redirect to `GET /documents`, which is 405 `method_not_allowed` because only POST is registered there.)
- Fixtures: `repo` (`InMemoryDocumentRepository()`) injected via `create_app(repository=repo)`; `client` built from `TestClient`. No network, no API key.
