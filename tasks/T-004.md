# T-004: LLM field extraction and the per-field uncertainty model

Status: done
Depends on: T-003

## Goal
A client can call `POST /documents/{id}/extract` and receive the four credential fields, each with a status (`found | not_found | unreadable | invalid`), the raw text the model saw, and issue codes, plus a `missing_fields` list; the LLM sits behind a protocol so the whole flow runs with a fake.

## Scope
In:
- `src/app/models.py`: `FIELD_NAMES`, `FieldStatus` (with `rank`), `FieldResult` (value forced to `None` unless `found`), `ExtractionResult` (`missing_fields` computed, `fields()`, `all_with()`), `ExtractionResponse`.
- `src/app/extraction.py`: `ExtractorError`, `FieldExtractor` protocol, `FakeFieldExtractor`, `build_field_extractor()`.
- `src/app/api.py`: `POST /documents/{id}/extract` (OCR -> extractor -> response), including the `no_text` short-circuit.
- `create_app(..., field_extractor=None)` keyword; `None` -> `build_field_extractor(settings)`; stored on `app.state.field_extractor`.
- `tests/test_T-004_field_extraction.py`.
Out:
- Normalization/validation of values (state names, dates, expiry) — T-005. This ticket returns the extractor's fields as-is.
- The real Anthropic extractor (T-007); `build_field_extractor` raises `ValueError` for `"anthropic"` until then.
- Storing extraction results; confidence scores.

## Interface (copied from docs/SPEC.md so the ticket is self-contained)

```python
# src/app/models.py (added)
from enum import StrEnum
from pydantic import Field, computed_field, model_validator

FIELD_NAMES: tuple[str, ...] = ("provider_name", "license_number", "state", "expiration_date")

class FieldStatus(StrEnum):
    FOUND = "found"
    NOT_FOUND = "not_found"
    UNREADABLE = "unreadable"
    INVALID = "invalid"

    @property
    def rank(self) -> int:
        """found=3, invalid=2, unreadable=1, not_found=0 (higher = more certain)."""

class FieldResult(BaseModel):
    value: str | None = None
    status: FieldStatus
    raw: str | None = None
    issues: list[str] = Field(default_factory=list)
    # after-validator: if status != FOUND then value is forced to None (never rejected).

class ExtractionResult(BaseModel):
    provider_name: FieldResult
    license_number: FieldResult
    state: FieldResult
    expiration_date: FieldResult

    @computed_field
    @property
    def missing_fields(self) -> list[str]:
        """Names from FIELD_NAMES, in that order, whose status != found."""

    def fields(self) -> dict[str, FieldResult]:
        """{name: FieldResult} in FIELD_NAMES order."""

    @classmethod
    def all_with(cls, status: FieldStatus, *, issues: list[str] | None = None) -> "ExtractionResult":
        """Every field = FieldResult(status=status, issues=list(issues or []))."""

class ExtractionResponse(ExtractionResult):
    document_id: str
    text_source: Literal["pdf_text_layer", "ocr"]
```

`model_dump()` / JSON of `ExtractionResult` includes `missing_fields`. `FieldStatus` serializes
as its string value.

Response example:

```json
{
  "document_id": "…",
  "text_source": "ocr",
  "provider_name":   {"value": "Jane Doe",    "status": "found",     "raw": "Jane Doe",   "issues": []},
  "license_number":  {"value": "LCSW-12345",  "status": "found",     "raw": "LCSW-12345", "issues": []},
  "state":           {"value": null,          "status": "not_found", "raw": null,         "issues": []},
  "expiration_date": {"value": null,          "status": "unreadable","raw": "12/3?/2027", "issues": []},
  "missing_fields": ["state", "expiration_date"]
}
```

Flow: 404 `document_not_found` if unknown id; `extract_text` (OcrError -> 422 `ocr_failed`);
if `text.strip() == ""` respond with `ExtractionResult.all_with(NOT_FOUND, issues=["no_text"])`
without calling the extractor; else `field_extractor.extract_fields(text)` — any exception ->
422 `extraction_failed` with `details == {"reason": "<exception class name>"}`. (T-005 inserts
`validate_result` before the response; this ticket returns the extractor's result unchanged.)

## Acceptance criteria
AC1. Given `create_app(ocr_engine=FakeOcrEngine("some text"), field_extractor=FakeFieldExtractor(result))` where `result` has all four fields `found` with values `Jane Doe`, `LCSW-12345`, `CA`, `2099-12-31` and `raw` equal to each value, and an uploaded PNG When a client posts to `/documents/{id}/extract` Then the response is 200, every field has `status == "found"` with the given `value`, `raw` and `issues == []`, `missing_fields == []`, `document_id` equals the uploaded id, `text_source == "ocr"`, and `extractor.calls == ["some text"]`.
AC2. Given a fake extractor whose result has `state` as `FieldResult(status="not_found")` and the other three fields `found` (canonical values as in AC1) When a client posts to `/documents/{id}/extract` Then `state == {"value": null, "status": "not_found", "raw": null, "issues": []}` and `missing_fields == ["state"]`.
AC3. Given a fake extractor whose result has `expiration_date` as `FieldResult(status="unreadable", raw="12/3?/2027", issues=["smudged"])` and the other three fields `found` When a client posts to `/documents/{id}/extract` Then `expiration_date == {"value": null, "status": "unreadable", "raw": "12/3?/2027", "issues": ["smudged"]}` and `missing_fields == ["expiration_date"]`.
AC4. Given `create_app(ocr_engine=FakeOcrEngine("some text"), field_extractor=FakeFieldExtractor(error=RuntimeError("llm down")))` and an uploaded PNG When a client posts to `/documents/{id}/extract` Then the response is 422 with `error.code == "extraction_failed"` and `error.details == {"reason": "RuntimeError"}`; and Given the OCR engine raises instead Then the response is 422 `ocr_failed` and `extractor.calls == []`.
AC5. Given `create_app(ocr_engine=FakeOcrEngine("   \n"), field_extractor=extractor)` and an uploaded PNG When a client posts to `/documents/{id}/extract` Then the response is 200, every field is `{"value": null, "status": "not_found", "raw": null, "issues": ["no_text"]}`, `missing_fields` lists all four names in `FIELD_NAMES` order, and `extractor.calls == []`.
AC6. Given the models are used directly When `FieldResult(value="x", status="invalid")` is constructed Then `.value is None`; When `FieldStatus.FOUND.rank > FieldStatus.INVALID.rank > FieldStatus.UNREADABLE.rank > FieldStatus.NOT_FOUND.rank` is evaluated Then it is true; and When `ExtractionResult.all_with(FieldStatus.NOT_FOUND).model_dump()` is taken Then it contains `"missing_fields": ["provider_name", "license_number", "state", "expiration_date"]` and `FieldResult(status="found", value="A").model_dump()["status"] == "found"`.

- AC3: happy unreadable with issues preserved; edge: unreadable with `issues=[]` and `raw=None`; failure path: `status="bogus"` in `FieldResult` raises `pydantic.ValidationError`.
- AC4: happy 422 `extraction_failed`; edge: custom exception class name appears as `reason`; failure path: OCR error short-circuits before the extractor (calls empty).
- AC5: happy whitespace-only text; edge: exactly `""`; failure path: text `"x"` (non-blank) does call the extractor.
- AC6: direct model tests; edge: `ExtractionResult.fields()` keys equal `FIELD_NAMES`; failure path: `build_field_extractor(Settings(extractor_backend="anthropic"))` raises `ValueError` while `Settings()` yields a `FakeFieldExtractor`.
