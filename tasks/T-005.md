# T-005: Deterministic normalization and validation rules

Status: done
Depends on: T-004

## Goal
The untrusted LLM output is normalized and validated deterministically after the call: full state names become two-letter codes, dates become ISO 8601, unparseable dates and unknown states become `invalid`, expired licenses are flagged, and a field's status can only ever be downgraded.

## Scope
In:
- `src/app/validation.py`: `US_STATE_CODES`, `DATE_FORMATS`, `normalize_state()`, `normalize_date()`, `validate_field()`, `validate_result()`.
- `create_app(..., clock=None)` keyword; `None` -> `datetime.date.today`; stored on `app.state.clock`.
- `POST /documents/{id}/extract` applies `validate_result(result, today=clock())` before responding.
- `tests/test_T-005_validation.py`.
Out:
- License-number format rules per state (pass-through after strip; SPEC A12).
- Territories (PR, GU, VI, AS, MP) and non-US jurisdictions (`unknown_state`; SPEC A11).
- Two-digit years, natural-language dates outside `DATE_FORMATS`, time zones (SPEC A10).
- Changing the extractor, the OCR engine, or the response shape.

## Interface (copied from docs/SPEC.md so the ticket is self-contained)

```python
# src/app/validation.py
from datetime import date

US_STATE_CODES: dict[str, str]
    # lower-case full name -> code, 50 states + "district of columbia" -> "DC"

DATE_FORMATS: tuple[str, ...] = (
    "%Y-%m-%d", "%m/%d/%Y", "%m-%d-%Y",
    "%B %d, %Y", "%b %d, %Y", "%B %d %Y", "%b %d %Y", "%d %B %Y", "%d %b %Y",
)

def normalize_state(raw: str) -> str | None:
    """strip whitespace and trailing '.,;', case-insensitive. Two-letter code in the code set
    -> upper-cased code; full name in US_STATE_CODES -> code; else None."""

def normalize_date(raw: str) -> date | None:
    """strip, collapse internal whitespace to one space, try DATE_FORMATS in order with
    datetime.strptime; first hit wins; None if nothing matches."""

def validate_field(name: str, field: FieldResult, *, today: date) -> FieldResult:
    """Returns a NEW FieldResult. If field.status != found: returned unchanged (equal).
    Otherwise, with raw := field.raw if field.raw is not None else field.value, and existing
    issues preserved (new codes appended, no duplicates):
      value None or blank        -> status invalid, value None, + "empty_value"
      provider_name / license_number -> status found, value stripped
      state    -> normalize_state; None -> invalid, value None, + "unknown_state"
                  else found, value = code
      expiration_date -> normalize_date; None -> invalid, value None, + "unparseable_date"
                  parsed < today -> invalid, value None, + "expired" (raw keeps the original)
                  else found, value = ISO "YYYY-MM-DD"
    Invariant: result.status.rank <= field.status.rank, always."""

def validate_result(result: ExtractionResult, *, today: date) -> ExtractionResult:
    """validate_field applied to each of FIELD_NAMES; returns a new ExtractionResult
    (missing_fields recomputes automatically)."""
```

`POST /documents/{id}/extract` now applies `validate_result(result, today=clock())` to the
extractor's output before building the `ExtractionResponse` (shape unchanged from T-004). The
`no_text` short-circuit result is also passed through `validate_result` (a no-op, since nothing
is `found`).

Status certainty rank (from `FieldStatus.rank`): `found=3 > invalid=2 > unreadable=1 > not_found=0`.
Issue codes set here: `empty_value`, `unknown_state`, `unparseable_date`, `expired`.
Existing issue strings from the extractor are preserved.

## Acceptance criteria
AC1. Given `FieldResult(status="found", value="California", raw="California")` When `validate_field("state", field, today=date(2026, 9, 11))` is called Then the result is `{"value": "CA", "status": "found", "raw": "California", "issues": []}`; `normalize_state(" new york. ")` returns `"NY"`, `normalize_state("tx")` returns `"TX"`, `normalize_state("District of Columbia")` returns `"DC"`; and `FieldResult(status="found", value="Ontario")` validates to `status == "invalid"`, `value is None`, `issues == ["unknown_state"]`.
AC2. Given `FieldResult(status="found", value="Jan 32 2024")` When `validate_field("expiration_date", field, today=date(2026, 9, 11))` is called Then the result is `{"value": None, "status": "invalid", "raw": "Jan 32 2024", "issues": ["unparseable_date"]}` (raw copied from value because it was `None`); and `normalize_date("12/31/99")` returns `None`.
AC3. Given `FieldResult(status="found", value="01/31/2020", raw="01/31/2020")` When `validate_field("expiration_date", field, today=date(2026, 9, 11))` is called Then the result is `{"value": None, "status": "invalid", "raw": "01/31/2020", "issues": ["expired"]}`; a value equal to today (`"2026-09-11"`) stays `found` with `issues == []`; and a value of `"2026-09-10"` is `invalid` with `["expired"]`.
AC4. Given a `found` expiration_date in each of `"2027-06-30"`, `"06/30/2027"`, `"06-30-2027"`, `"June 30, 2027"`, `"Jun 30 2027"`, `"30 June 2027"` When validated with `today=date(2026, 9, 11)` Then every result is `status == "found"` with `value == "2027-06-30"`; and `normalize_date("  June   30,  2027 ")` returns `date(2027, 6, 30)`.
AC5. Given every `FieldStatus` in `{found, not_found, unreadable, invalid}` combined with every field name in `FIELD_NAMES` and values in `{None, "", "Nonsense!!", "California", "01/31/2020", "2099-12-31"}` When `validate_field(name, FieldResult(status=s, value=v), today=date(2026, 9, 11))` is called Then `result.status.rank <= FieldResult(status=s, value=v).status.rank` for every combination, every non-`found` input is returned equal to its input, and no `found` output is produced from a non-`found` input.
AC6. Given `create_app(ocr_engine=FakeOcrEngine("text"), field_extractor=FakeFieldExtractor(result), clock=lambda: date(2026, 9, 11))` where `result` has `provider_name = found " Jane Doe "`, `license_number = found "LCSW-12345"`, `state = found "California"`, `expiration_date = found "01/31/2020"`, and an uploaded PNG When a client posts to `/documents/{id}/extract` Then the response is 200 with `provider_name.value == "Jane Doe"`, `state.value == "CA"`, `state.status == "found"`, `expiration_date == {"value": null, "status": "invalid", "raw": "01/31/2020", "issues": ["expired"]}`, and `missing_fields == ["expiration_date"]`.

## Test plan
- File: `tests/test_T-005_validation.py`. Fixed `TODAY = date(2026, 9, 11)`; app tests inject `clock=lambda: TODAY`.
- AC1: happy full name -> code; edge: code already canonical (`"CA"`) unchanged and lower-case code upper-cased, trailing punctuation stripped; failure path: unknown state -> `invalid` + `unknown_state`, and `normalize_state("")` returns `None`.
- AC2: happy `Jan 32 2024`; edge: `raw` provided by the extractor is preserved verbatim (not overwritten); failure path: two-digit year and `"soon"` are both unparseable; existing issues (e.g. `["faint"]`) are kept and `unparseable_date` appended once.
- AC3: happy expired (`value is None`, `raw` keeps the original date string); edge: boundary `today` not expired, `today - 1 day` expired; failure path: an extractor-supplied `raw` that differs from `value` survives verbatim, and `expired` is appended only once when it is already in `issues`.
  (Corrected during T-005: the failure path as first written repeated the happy path's assertions verbatim, so it could not fail independently.)
- AC4: parametrize over all six formats; edge: whitespace collapse; failure path: `"2027-13-01"` (bad month) is `unparseable_date`.
- AC5: parametrize over the full cross product (4 statuses x 4 names x 6 values); assert rank invariant, identity for non-found inputs (`==`), and that `validate_result` on `ExtractionResult.all_with(FieldStatus.UNREADABLE)` returns an equal result; edge: `FieldResult(status="found", value=None)` -> `invalid` + `empty_value`; failure path: `validate_field` returns a new object (`is not` the input).
- AC6: happy end-to-end through the endpoint; edge: `no_text` short-circuit result (engine returns `""`) is unchanged by validation (all `not_found`, `issues == ["no_text"]`); failure path: `create_app()` without a clock still answers (uses today's date) for a `2099-12-31` expiry -> `found`.
- Fixtures: `FakeOcrEngine`, `FakeFieldExtractor`, `clock` injected via `create_app`. No network, no API key.
