# T-006: Upload UI page

Status: todo
Depends on: T-002

## Goal
A human opens `GET /` in a browser, sees the maximum file size before choosing a file, uploads a jpg/png/pdf, and sees a table with each field's value, status and issues plus the list of missing fields.

## Scope
In:
- `src/app/static/index.html`: one hand-written HTML page with inline vanilla JS and minimal inline CSS; no external assets, no framework, no build step.
- `src/app/ui.py`: router serving the page at `GET /`; included by `create_app`.
- `tests/test_T-006_ui.py` asserting the served page's structural contract.
Out:
- Server-side templating or placeholder substitution (the page is static; it fetches `GET /config` at load).
- Browser automation / JS execution in tests; tests only assert the HTML served.
- Serving any other static asset, favicon, or `/index.html` alias.
- Styling beyond readability; accessibility audit; i18n.
- Changes to any API endpoint.

## Interface (copied from docs/SPEC.md so the ticket is self-contained)

```python
# src/app/ui.py
from pathlib import Path
from fastapi import APIRouter

INDEX_PATH: Path = Path(__file__).parent / "static" / "index.html"
router: APIRouter   # GET / -> FileResponse(INDEX_PATH, media_type="text/html")
```

| Method | Path | Response |
|--------|------|----------|
| GET    | /    | 200, `Content-Type: text/html; charset=utf-8`, body = `src/app/static/index.html` |

Contract of `src/app/static/index.html` (plain HTML + inline vanilla JS, no external assets):

- `<p id="max-upload">` — on load the script does `fetch("/config")` and writes
  `Maximum file size: <N> MB (<max_upload_bytes> bytes). Accepted: <types>` into it. The upload
  button `<button id="upload" type="submit" disabled>` is disabled until `/config` has loaded.
- `<input type="file" id="file" name="file" accept="application/pdf,image/jpeg,image/png" required>`
- Client-side guard: if `file.size > max_upload_bytes` the script shows a message in
  `<p id="error" role="alert">` and does not upload.
- Submit: `POST /documents` (multipart, part name `file`), then `POST /documents/{id}/extract`.
  Any envelope error shows `error.message` (and `error.code`) in `#error`.
- `<table id="results">` with exactly these rows in this order, each with three cells:
  `<tr data-field="provider_name">`, `<tr data-field="license_number">`,
  `<tr data-field="state">`, `<tr data-field="expiration_date">`; cells
  `<td data-cell="value">`, `<td data-cell="status">`, `<td data-cell="issues">`.
- `<p id="missing-fields">` lists `missing_fields` joined by ", " (or "none").
- `<p id="document-meta">` shows filename and size after upload.

The API the page talks to (already delivered by T-002, T-004, T-005):
`GET /config -> {"max_upload_bytes", "allowed_content_types"}`; `POST /documents` (multipart
`file`) -> 201 `{"id", "filename", "content_type", "size_bytes"}`; `POST /documents/{id}/extract`
-> 200 with the four field objects `{value, status, raw, issues}` and `missing_fields`; errors
are `{"error": {"code", "message", "details"}}`.

## Acceptance criteria
AC1. Given an app from `create_app()` When a client calls `GET /` Then the response is 200, the `Content-Type` header starts with `text/html`, and the body equals the contents of `src/app/ui.INDEX_PATH` decoded as UTF-8 and is non-empty.
AC2. Given the served page When its body is inspected Then it contains `<input` with `type="file"`, `id="file"`, `name="file"` and `accept="application/pdf,image/jpeg,image/png"`, and a `<button id="upload"` that is `disabled` in the markup.
AC3. Given the served page When its body is inspected Then it contains `id="max-upload"`, the literal `"/config"` (the fetch that states the limit before upload), the literal `max_upload_bytes`, and `id="error"` (where the client-side size rejection and API errors are shown).
AC4. Given the served page When its body is inspected Then it contains `id="results"`, the four rows `data-field="provider_name"`, `data-field="license_number"`, `data-field="state"`, `data-field="expiration_date"` in that order, the cells `data-cell="value"`, `data-cell="status"`, `data-cell="issues"`, `id="missing-fields"`, and the literals `"/documents"` and `/extract` (the two calls the page makes); and the page contains no `<script src=` or `<link` to an external asset.

## Test plan
- File: `tests/test_T-006_ui.py`. Plain substring / regex assertions on `response.text`; no browser, no JS execution.
- AC1: happy 200 + content type; edge: `charset=utf-8` present in the header; failure path: `POST /` -> 405 envelope `method_not_allowed` (JSON, not HTML).
- AC2: happy file input attributes (attribute order independent: assert each attribute inside the same `<input ...>` tag via regex); edge: `required` attribute present; failure path: no second file input exists.
- AC3: happy `#max-upload` + `/config`; edge: `id="error"` and `role="alert"`; failure path: the page does not hard-code `10485760` or `10 MB` (the limit comes from `/config`).
- AC4: happy rows in order (compare `str.index` of each `data-field=`); edge: `#document-meta` present; failure path: no `<script src=`, no `<link rel="stylesheet"`.
- Fixtures: `client` from `create_app()`; read `INDEX_PATH` for AC1. No network, no API key.
